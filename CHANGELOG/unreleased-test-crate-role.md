- A crate can now declare that its sources are test code. Test harnesses, shared fixture crates and unpublished tooling crates compile as ordinary libraries, so neither their own syntax nor the Cargo module graph says they are tests, and their `src/` counted as production code — in `arthur-debert/standout`, about 2,730 lines across three crates, which previously had to be excluded with three `-e` globs on every invocation and then vanished from the report entirely. Adding `[package.metadata.rustloc] role = "tests"` to such a crate's manifest counts the production logic of every analyzed file under its directory as tests instead. Docs, comments, blanks, examples and lines already classified as tests are unchanged, and so is each file's line total, exactly as an existing `#[cfg(test)]` module reclassification behaves. The role applies to `count`, `diff`, `--by-commit`, `--by-crate` and `--by-file`. `role = "tests"` is the only value that reclassifies: `role = "code"` is the default written out, and any other value is ignored, leaving the crate classified by its files alone. Diffs read the declaration from the revision each side's content came from, so the commit that adds the role reports the crate's lines as code removed and tests added while earlier commits keep their numbers. A project whose module graph fails to load still honours the roles its manifests declare.
